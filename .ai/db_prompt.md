### Промт для проектирования структуры базы данных (SQL)

**Роль:** ты — опытный архитектор баз данных и SQL-разработчик.

**Задача:** спроектировать структуру базы данных для приложения [название приложения, например: «Учёт личного бюджета»].

**Требования к структуре:**
1. Определи основные сущности (таблицы), необходимые для работы приложения.
2. Опиши связи между сущностями (один-к-одному, один-ко-многим, многие-ко-многим).
3. Для каждой таблицы перечисли поля:
    - название поля;
    - тип данных;
    - ограничения (NOT NULL, UNIQUE, DEFAULT и др.);
    - краткое описание назначения поля.
4. Укажи первичные (PK) и внешние ключи (FK).
5. Если необходимо, предложи индексы для ускорения запросов.
6. Сформулируй правила целостности данных (например: нельзя удалить категорию, если есть связанные транзакции).

**Формат ответа:**
- Сначала краткое описание архитектуры (1–2 абзаца).
- Затем SQL-код для создания таблиц (CREATE TABLE) с комментариями к каждому полю.
- В конце — краткое описание связей и ограничений.

**Пример описания требований (для приложения учёта бюджета):**
- Пользователи могут регистрироваться и входить в систему.
- Каждый пользователь может создавать свои категории доходов и расходов.
- Пользователь добавляет транзакции (доход/расход), указывая сумму, дату, категорию и комментарий.
- Категорию нельзя удалить, если к ней привязаны транзакции.
- Необходимо хранить историю всех операций.

**Результат:** сгенерируй SQL-схему, соответствующую этим требованиям.
