### Промт для разработки Backend с Supabase

**Роль:** ты — опытный backend-разработчик, специализирующийся на Supabase, REST API, аутентификации и интеграции с современными фронтенд-фреймворками.

**Задача:** разработать backend-часть для приложения «Учёт личного бюджета» на базе Supabase.

**Контекст:**
- Структура базы данных (таблицы Users, Categories, Transactions) уже спроектирована и создана в Supabase.
- Для фронтенда подготовлено описание API и логики работы (ознакомиться можно в файле `frontend_descr.md`).
- Необходимо реализовать REST API, который будет использоваться как веб-, так и мобильным приложением.

**Требования к реализации:**

1. **Аутентификация (Supabase Auth):**
    - Реализовать регистрацию пользователя (email/пароль).
    - Реализовать вход пользователя (email/пароль).
    - Реализовать выход пользователя.
    - Реализовать восстановление пароля.
    - Все операции должны возвращать JWT-токен или session-объект для клиента.

2. **API для работы с транзакциями (CRUD):**
    - Реализовать эндпоинты для операций с транзакциями пользователя:
        - `GET /transactions` — получить список транзакций текущего пользователя (с фильтрацией по дате/категории).
        - `POST /transactions` — создать новую транзакцию.
        - `PUT /transactions/:id` — обновить существующую транзакцию.
        - `DELETE /transactions/:id` — удалить транзакцию.
    - Все операции должны быть доступны только авторизованным пользователям.

3. **API для работы с категориями:**
    - Реализовать эндпоинты для управления категориями пользователя:
        - `GET /categories` — получить список категорий.
        - `POST /categories` — создать категорию.
        - `PUT /categories/:id` — обновить категорию.
        - `DELETE /categories/:id` — удалить категорию (только если нет связанных транзакций).

4. **Безопасность и доступ:**
    - Настроить Row Level Security (RLS) для всех таблиц, чтобы пользователь мог работать только со своими данными.
    - Реализовать middleware или использовать встроенные механизмы Supabase для проверки авторизации на всех эндпоинтах.
    - Настроить CORS для работы с фронтендом.

5. **Обработка ошибок:**
    - Реализовать корректную обработку ошибок:
        - 401 (неавторизован), 403 (недостаточно прав), 404 (не найдено), 422 (ошибки валидации), 500 (серверная ошибка).
    - Возвращать понятные сообщения об ошибках в формате JSON.

6. **Документация и примеры:**
    - Подготовить описание архитектуры решения.
    - Описать все API endpoints (метод, путь, параметры, пример запроса/ответа).
    - Привести примеры использования API для фронтенда (например, на JS/TS с использованием supabase-js клиента).

7. **Интеграция с фронтендом:**
    - Учесть требования из файла `frontend_descr.md` при проектировании ответов API и логики работы.

**Формат ответа:**
1. Краткое описание архитектуры решения.
2. SQL-скрипты для настройки RLS-политик (если требуется).
3. Описание всех API endpoints (таблица или список).
4. Примеры кода для реализации API (например, на Node.js/Express или Deno, с использованием supabase-js).
5. Примеры запросов/ответов в формате JSON.
6. Краткая инструкция по развертыванию и настройке.

**Результат:** сгенерируй полный комплект материалов для разработки backend-части приложения на Supabase, готовый к интеграции с фронтендом и мобильным приложением.
